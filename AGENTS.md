# Инструкции для агентов

## О проекте

- Это клиентский макет CRM на React 18. Приложение находится в `front_on_react/`.
- Данные демонстрационные и хранятся в массивах `front_on_react/src/mockData.js`. В репозитории нет серверной части, API или постоянного хранилища.
- Основные страницы и компоненты собраны в `front_on_react/src/index.jsx`; общие стили — в `front_on_react/src/styles.css`; HTML-шаблон — `front_on_react/public/index.html`.
- Интерфейс и примерные данные написаны на русском языке. Сохраняйте UTF-8 и существующую терминологию.
- Часть кнопок и форм сейчас только иллюстрирует предполагаемый интерфейс и не выполняет операций. Не описывайте и не подразумевайте их как работающую функциональность без реализации.

## Стек и соглашения

- Используются функциональные React-компоненты и хуки, JSX, Babel с автоматическим JSX runtime и Bootstrap 5.
- Связи между записями мок-данных задаются идентификаторами (`organizationId`, `contactId`, `assigneeId` и другими). При изменении примеров поддерживайте эти ссылки согласованными.
- Пользовательские визуальные настройки и переменные темы размещайте в `src/styles.css`; Bootstrap подключается глобально из `src/index.jsx`.
- Зависимости фиксируются в `front_on_react/package-lock.json`. Не редактируйте `node_modules/` и не добавляйте зависимости, если задачу можно решить текущим стеком.
- Не добавляйте предположения о backend, авторизации или реальном хранении файлов: сейчас разделы CRM являются демонстрационными.

## Запуск и сборка

Все npm-команды выполняйте из `front_on_react/`:

- `npm start` — запуск dev-сервера на `http://127.0.0.1:3000`.
- `npm run build` — production-сборка через Webpack в `front_on_react/dist/`.

В `package.json` определены только скрипты `start` и `build`; отдельные скрипты тестирования и линтинга отсутствуют.

## Работа с изменениями

- Для небольших изменений придерживайтесь текущего устройства приложения и не вводите новый фреймворк или систему сборки.
- При добавлении или изменении UI учитывайте узкие экраны: адаптивные правила находятся в конце `src/styles.css`.
- Если добавляется поведение, явно реализуйте его на клиенте и согласуйте с существующей моделью данных; не оставляйте интерактивный контрол без обработчика, если его назначение заявлено как рабочее.
- После изменения зависимостей обновляйте lock-файл штатным npm-инструментом. Не коммитьте результаты сборки из `dist/`, если это отдельно не требуется.
